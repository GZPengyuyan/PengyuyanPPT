# 阶段 3：A 版先交付，用户选择是否精修

## 核心目标

先快速交付一张风格、颜色、排版、结构和核心内容基本符合蓝图的可编辑 A 版。A 版通过 PowerPoint 打开与兼容性检查后立即暂停；只有用户选择 B，才启动蓝图一致性精修。

## 开始前

1. 确认全部目标页面蓝图已经生成并由用户确认，记录 `blueprint_set_confirmed: true`。
2. 确认蓝图/风格基准和 `visual_master`。
3. 确认 `slide_content_lock`，蓝图入口可用精简版。
4. 从已确认蓝图中选择一张代表性样板页：优先信息密度高、组件完整、能体现整套视觉系统的页面。
5. 告知用户：先交付 A 版可编辑样板页；第一次 A/B 选择决定后续全部页面的 PPT 转换标准。

若全部蓝图尚未确认，停止阶段 3，返回蓝图阶段。不得因为代表蓝图已确认就提前制作可编辑 PPT。

## 建立 visual_master

样板页生成时记录：

- 幻灯片尺寸、背景、边距和列网格；
- 色板、字体、字号层级和行距；
- 标题区、页脚、来源、页码和 SO WHAT；
- 面板、卡片、表格、KPI、图表和连接线样式；
- 主图标风格族；
- A 版允许的近似范围。

常用高密度结构应做成复用组件：三栏、步骤链、时间线、分层架构、矩阵、案例卡、KPI、表格、对比条和结论条。

## A 版的硬性视觉条件

A 版不是低保真草稿。必须基本匹配蓝图：

- 整体视觉风格；
- 主色、辅助色和背景色；
- 页面构图和区域划分；
- 标题、正文、表格、主图和结论条的位置关系；
- 主要模块尺寸比例；
- 阅读顺序和视觉层级；
- 页面信息密度；
- P0：标题、关键数字、主图/主流程、SO WHAT、品牌标识和用户点名区域；
- 主要文字、数字、表格和图表信息可编辑。

允许暂不追求最后约 10%：

- 普通图标不完全相同，但语义与风格一致；
- 复杂曲线和装饰图形使用相似的稳定原生形状；
- 阴影、圆角、渐变、边框和微小间距存在轻微差异；
- 不影响阅读的换行差异；
- 不承载业务含义的纹理适度简化。

## A 版执行循环

1. 读取当前样板页内容锁定与蓝图。
2. 按蓝图构图完成可编辑 PPTX。
3. 运行非 strict 结构检查。
4. 在 PowerPoint 中打开，确认无修复警告和兼容性问题。
5. 做一次快速完整性查看：关键对象未消失，中文/图标正常，无明显乱码、严重溢出或遮挡。
6. 交付 A 版 PPTX 和兼容性结论。
7. 立即停止，不生成蓝图对照图，不做元素测量、独立视觉 QA 或多轮一致性修正。
8. 询问用户选择：
   - A：当前效果满足，按 A 标准继续/归档；
   - B：继续一致性精修，并按 B 标准继续。

为检查兼容性而临时生成的缩略图或预览，只用于确认文件正常，不得自动演变为 B 阶段。

## 用户选择 A

### 单页

- 用户满意后直接完成并归档。
- 不补做渲染对照或精修证据。

### 多页

- 锁定样板页的 `visual_master`、组件库、图标风格和近似容差。
- 将其余已确认蓝图按 A 标准批量转换为可编辑 PPT，不再逐页暂停。
- 每页只做结构、兼容性、内容完整性和可编辑性检查。
- 修复文件损坏、关键对象缺失、乱码、严重溢出/遮挡等 Critical/High 问题。
- 不默认生成每页渲染对照、局部裁切或独立视觉 QA。

## 用户选择 B

先在 A 版样板页上执行：

1. 生成 PowerPoint 实际渲染图；
2. 生成蓝图与 PPT 并排对照；
3. 检查 P0/P1 的位置、尺寸、颜色、比例、层级和文字流；
4. 修正主图、表格、流程、结论条、Logo 和明显换行偏差；
5. 用户确认精修后的样板页；
6. 把修改固化为 B 标准和 `visual_master`。

随后：

- 将其余已确认蓝图按 B 标准批量转换为可编辑 PPT；
- 不再重复询问 A/B；
- 每页执行必要的渲染、蓝图对照和 P0/P1 修正；
- 用户只对个别页面不满意时，只返工指定页面。

用户明确要求 1:1、像素级、品牌/UI 精确还原时，再升级到 `precision`。

## 可编辑性

必须原生可编辑：

- 标题、正文、关键数字、来源、页脚和 SO WHAT；
- 表格文字和数字；
- 图表数据标签、图例和关键标注；
- 业务流程节点文字。

可以作为局部视觉资产：

- 非数据型复杂纹理；
- 不承载事实的装饰插画；
- 难以原生重建且不需编辑的局部图形。

不得把整页蓝图、大面积页面截图或包含关键文字的截图作为背景。

## 图形与图标

- 原生形状能清楚表达时优先原生形状。
- 普通图标走 `references/icon-strategy.md`，语义与风格一致即可。
- 图标必须在 PowerPoint 中稳定显示；出现问号、缺图或断线时优先换兼容 PNG/SVG 或原生图标。
- 品牌 Logo 必须使用准确资产；没有官方素材时应明确标注为临时近似，不得伪造。
- 核心曲线在 A 版可用稳定原生形状近似；B/precision 才做更精细追踪。

## 多蓝图批量与合并

- 进入本阶段前，全部蓝图必须已生成并确认。
- 未收到可编辑样板页第一次 A/B 选择前，不制作剩余页面的可编辑 PPT。
- 用户选择确定后，后续所有蓝图统一沿用该标准。
- 只有用户明确要求逐页确认，才逐页暂停。
- 批量完成后合并成完整 PPTX。
- 合并后检查页数、顺序、字体、资源、关键内容和 PowerPoint 打开兼容性。

不得一边生成剩余蓝图，一边转换 PPT；蓝图批量和 PPT 批量是两个串行阶段。

## 生成引擎

正式页优先使用 PptxGenJS/pptx-generator，允许 PowerPoint 原生文本、形状、表格、图表、SVG、兼容 PNG 和 custom geometry。禁止用 `python-pptx`、HTML 截图或整页图片作为正式生成替代。

## 精简制作记录

A 版只需记录：

- `blueprint_set_confirmed: true`；
- blueprint path/hash；
- content lock path/hash；
- visual master version；
- `quality_profile: A`；
- P0/P1 组件摘要；
- 可编辑对象摘要；
- 兼容性检查结果；
- 用户 A/B 选择。

B/precision 才记录渲染对照、视觉差异、精修证据和完整门禁结果。
