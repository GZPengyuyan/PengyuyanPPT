# A/B 分级质量保证

## 原则

A 阶段的 QA 只负责保证“已经像蓝图、可以使用、可以编辑、可以正常打开”，不负责追求最后一段视觉一致性。用户选择 B 后，才启动蓝图对照和深度视觉 QA。

本文件只在整套蓝图已经确认后使用。`blueprint_set_confirmed` 未完成时，不得通过任何 QA 结果绕过蓝图确认门并进入阶段 3。

## A 版硬门槛

- 整套蓝图已经由用户确认；
- PPTX 能在 PowerPoint 中打开且不提示修复。
- 尺寸、页数和顺序正确。
- 无文件损坏、无效对象边界或关键对象消失。
- 关键事实与 `slide_content_lock` 一致。
- 标题、正文、关键数字、表格/图表标签、来源和 SO WHAT 可编辑。
- 无整页蓝图背景。
- 中文、字体和图标可以正常显示。
- 无明显乱码、严重文字越界、对象出画布或遮挡。
- 已确认的信息区、案例、表格、关键数字和结论没有被删减。
- 整体风格、颜色、构图、排版、信息密度和 P0 关键对象与蓝图基本一致。

## A 版检查

1. 运行非 strict 结构检查：

   `python3 scripts/validate_pptx.py page.pptx --json-out qa.json`

2. 使用 PowerPoint 打开文件，确认无修复警告。
3. 快速查看页面是否存在缺图、乱码、异常字体、严重溢出或遮挡；可以同时参考原蓝图做一次肉眼整体核验，确认风格、颜色、构图和排版没有明显偏离。
4. 确认关键文字、数字、表格和图表信息可编辑。
5. 交付 A 版并暂停，询问 A/B。

A 阶段不得自动执行：

- 蓝图与 PPT 并排对照；
- 局部裁切和差异图；
- 全元素 registry；
- P0/P1 坐标测量；
- 每个图标 bbox 或像素差；
- 独立视觉 QA；
- 多轮视觉修正；
- strict validator。

如果为了检查 PowerPoint 兼容性生成了临时预览，只用于判断文件是否正常，不得据此自动进入一致性精修。

A 阶段的肉眼整体核验不得生成并排对照资产、视觉评分、局部差异图或修正循环。

## A 版阻塞问题

只有以下问题阻塞 A 版交付：

### Critical

- 文件打不开或提示修复；
- 内容错误或关键内容缺失；
- 关键文字/数据不可编辑；
- 整页截图冒充可编辑页面；
- 严重乱码；
- 关键主图、表格、结论条等对象消失。

### High

- 风格、主色、页面构图或核心排版明显偏离蓝图；
- 标题、SO WHAT、关键数字或主流程明显错误；
- 严重溢出、遮挡或阅读顺序错误；
- 图标、SVG、字体产生问号、缺图或兼容异常；
- 已确认的信息密度被明显降低。

普通图标近似、轻微色差、圆角、阴影、装饰线和微小间距差异不阻塞 A 版。

## 用户选择 A 后

### 单页

用户满意即可完成并归档，不补做视觉对照。

### 多页

- 后续页面按样板页 A 标准批量生成。
- 每页运行结构、内容、可编辑性与兼容性检查。
- 不要求每页 PowerPoint 渲染对照或独立视觉 QA。
- 最终合并版必须能在 PowerPoint 中打开且不提示修复。

## B 版检查

用户选择 B 后执行：

- 生成 PowerPoint 实际渲染图；
- 生成蓝图/PPT 并排对照；
- 检查 P0/P1 的位置、尺寸、颜色、比例、视觉层级和文字流；
- 为主图、关键表格、架构、流程和 SO WHAT 生成必要的局部对照；
- 修复 Critical/High 视觉偏差；
- 默认最多两轮修正；
- 由精修样板页锁定其余已确认蓝图的 B 转换标准。

后续 B 页面无需重复询问 A/B，但应执行必要的渲染、对照和修正。

## precision

用户明确要求像素级、1:1、品牌/UI 精确还原时使用：

```bash
python3 scripts/validate_pptx.py page.pptx \
  --manifest slide_manifest.json \
  --visual-qa visual_qa_gate.json \
  --strict --json-out qa.json
```

并要求：

- 完整 visual element registry；
- P0/P1/P2 测量；
- 关键区域局部裁切和差异图；
- 核心曲线、品牌/UI 和用户点名区域精确复核；
- strict errors 清零。

## 禁止自动升级

- A 版样板页不得因为是第一页、信息密度高、包含复杂 SVG 或建立 `visual_master` 而自动升级到 B。
- 只有兼容性风险需要在 A 阶段修复；视觉一致性精修必须等待用户选择。
- 用户未选择 B 时，不得调用独立视觉 QA 来推动精修。
- 代表蓝图确认不得替代整套蓝图确认；未确认全部页面时不得启动 A 版制作。

## 图标 QA

A 版普通图标只检查：

- 语义是否合理；
- 是否属于锁定风格族；
- 是否清晰且能在 PowerPoint 中稳定显示；
- 是否位于正确容器且不遮挡文字。

普通图标不要求逐像素匹配。Logo、品牌符号和核心业务标识按 P0 处理。

## 最终合并回归

无论 A 或 B，合并后至少检查：

- 页数和顺序；
- 主题字体、颜色、页眉页脚和页码；
- 图片、SVG、图表资源没有丢失；
- 无新增乱码、严重溢出或遮挡；
- 关键文本仍可编辑；
- 最终 deck 能在 PowerPoint 中正常打开且不提示修复。

A 标准不要求合并后逐页蓝图对照；B/precision 按各自的一致性规则执行。
